# Лабораторная работа 01

## Почему Web API должен возвращать 404, а не просто пустой объект?

Если клиент запрашивает конкретный ресурс, например `GET /api/courses/100`, сервер должен ясно сообщить, существует ли такой курс. Если курса нет, корректный ответ - `404 Not Found`.

Пустой объект вроде `{}` создает неоднозначность. Клиент не понимает, ресурс действительно не найден или сервер нашел объект, но у него нет заполненных полей. Это усложняет обработку ошибок, портит контракт API и может привести к неправильному поведению интерфейса или другой информационной системы.

С точки зрения REST-архитектуры URL указывает на конкретный ресурс. Если ресурс отсутствует, это не успешное получение пустых данных, а именно состояние "ресурс не найден". Поэтому HTTP-статус должен отражать реальный результат операции.

С точки зрения семантики HTTP код `404 Not Found` предназначен именно для такой ситуации. Клиент может программно обработать этот статус: показать сообщение пользователю, не выполнять дальнейшие действия или запросить другой идентификатор.

С точки зрения клиентоориентированности API правильный статус делает сервис понятным и предсказуемым. Клиенту не нужно анализировать содержимое тела ответа, чтобы угадать результат. Достаточно проверить HTTP Status Code.

## Контрольные вопросы

### 1. Что такое Web API?

Web API - это программный интерфейс веб-сервиса, доступный по HTTP. Он позволяет клиентским приложениям получать, создавать, изменять и удалять данные через endpoints.

### 2. Чем Web API отличается от обычной веб-страницы?

Обычная веб-страница обычно возвращает HTML для отображения в браузере. Web API возвращает данные, чаще всего JSON, чтобы ими могли пользоваться другие приложения: фронтенд, мобильное приложение или другой сервер.

### 3. Что такое клиент-серверная архитектура?

Клиент-серверная архитектура - это модель, в которой клиент отправляет запросы, а сервер их обрабатывает и возвращает ответы. Клиент отвечает за инициирование взаимодействия, сервер - за хранение данных, выполнение логики и формирование результата.

### 4. Что такое HTTP request?

HTTP request - это запрос клиента к серверу. Он содержит HTTP-метод, URL, заголовки и, если нужно, тело с данными.

### 5. Что такое HTTP response?

HTTP response - это ответ сервера на запрос клиента. Он содержит код состояния, заголовки и тело ответа с результатом выполнения операции.

### 6. Что такое endpoint?

Endpoint - это конкретная точка доступа API. Он определяется URL и HTTP-методом, например `GET /api/courses` или `DELETE /api/courses/{id}`.

### 7. Для чего используется HTTP GET?

`GET` используется для получения данных. Он должен быть безопасным для состояния сервера, то есть не создавать, не изменять и не удалять ресурсы.

### 8. Для чего используется POST?

`POST` используется для отправки данных на сервер. В REST API его обычно применяют для создания нового ресурса.

### 9. В чем отличие PUT от POST?

`POST` чаще всего создает новый ресурс, а `PUT` обновляет уже существующий ресурс по известному идентификатору. Например, `POST /api/courses` создает курс, а `PUT /api/courses/1` изменяет курс с `Id = 1`.

### 10. Для чего используется DELETE?

`DELETE` используется для удаления ресурса. Например, `DELETE /api/courses/2` удаляет курс с идентификатором `2`, если он существует.

### 11. Что означает HTTP Status Code 200?

`200 OK` означает, что запрос успешно обработан. При `GET` сервер обычно возвращает найденные данные, а при успешном `PUT` может вернуть обновленный объект.

### 12. Что означает 201?

`201 Created` означает, что сервер успешно создал новый ресурс. Такой ответ часто возвращается после `POST`.

### 13. Что означает 204?

`204 No Content` означает, что запрос успешно выполнен, но тело ответа отсутствует. Этот статус часто используют после успешного удаления через `DELETE`.

### 14. Что означает 404?

`404 Not Found` означает, что сервер не нашел запрошенный ресурс. Например, курс с указанным идентификатором отсутствует.

### 15. Что такое JSON?

JSON - это текстовый формат представления данных. Он использует объекты, массивы, строки, числа и логические значения. JSON удобен для обмена данными между клиентом и сервером.

```json
{
  "id": 1,
  "name": "Web Services",
  "teacher": "Teacher 1",
  "credits": 5
}
```

### 16. Что делает атрибут [HttpGet]?

Атрибут `[HttpGet]` указывает, что метод контроллера должен обрабатывать HTTP-запросы типа `GET`.

### 17. Для чего используется [Route]?

Атрибут `[Route]` задает маршрут контроллера или отдельного метода. Например, `[Route("api/[controller]")]` формирует путь `/api/courses` для `CoursesController`.

### 18. Что делает ControllerBase?

`ControllerBase` - базовый класс для Web API контроллеров в ASP.NET Core. Он предоставляет методы для формирования HTTP-ответов, например `Ok()`, `NotFound()`, `CreatedAtAction()` и `NoContent()`.

### 19. Что такое Swagger?

Swagger - это инструмент для описания, документирования и тестирования Web API. Он показывает список endpoints, схемы моделей, параметры запросов и позволяет отправлять запросы через веб-интерфейс.

### 20. Почему Web API удобно использовать для взаимодействия нескольких информационных систем?

Web API удобно использовать для интеграции систем, потому что оно работает по стандартному протоколу HTTP и передает данные в универсальном формате JSON. Благодаря этому один сервер может обслуживать веб-приложение, мобильное приложение, внешнюю систему учета или другой сервис.
